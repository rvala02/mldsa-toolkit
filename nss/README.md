# NSS Test Harness for ML-DSA Side-Channel Analysis Toolkit

This directory contains helper programs for side-channel timing analysis of NSS's ML-DSA implementation through the PKCS#11 signing path.

The harnesses support ML-DSA-44, ML-DSA-65, and ML-DSA-87.

## Building

1. **Build or install NSS with ML-DSA support.**
- The regular timing harnesses use the NSS PKCS#11 API.
- The *_no_encode harnesses require the patched NSS build that exports:
```
MLDSA_GetLastCoreCycles()
```
2. **Compile the harnesses.**
```
$ cd nss 

$ gcc -O2 -Wall -Wextra -std=gnu11 \ 
    timing.c readpem.c \ 
    -o timing \ 
    $(pkg-config --cflags --libs nss) \ 
    -ldl 

$ gcc -O2 -Wall -Wextra -std=gnu11 \ 
    timing_no_encode.c readpem.c \ 
    -o timing_no_encode \ 
    $(pkg-config --cflags --libs nss) \ 
    -ldl 

$ gcc -O2 -Wall -Wextra -std=gnu11 \ 
    key_timing.c readpem.c \ 
    -o key_timing \ 
    $(pkg-config --cflags --libs nss) \ 
    -ldl 

$ gcc -O2 -Wall -Wextra -std=gnu11 \ 
    key_timing_no_encode.c readpem.c \ 
    -o key_timing_no_encode \ 
    $(pkg-config --cflags --libs nss) \ 
    -ldl

$ gcc -O2 -Wall -Wextra -std=gnu11 \ 
    rejection_timing.c readpem.c \ 
    -o rejection_timing \ 
    $(pkg-config --cflags --libs nss) \ 
    -ldl 

$ gcc -O2 -Wall -Wextra -std=gnu11 \ 
    rejection_timing_no_encode.c readpem.c \ 
    -o rejection_timing_no_encode \ 
    $(pkg-config --cflags --libs nss) \ 
    -ldl
```

## Usage

### Timing with one PEM private key

The `timing` harness signs concatenated messages with one PEM-encoded ML-DSA private key.

```
$ ./timing -i messages.bin -o sigs.bin -t raw_times.bin -k sk.pem -n 32 -s 44
```

Arguments:

```
-i file File with concatenated messages to sign 
-o file File where to write the signatures 
-t file File where to write timing data 
-k file File with the ML-DSA private key in PEM format 
-n num Length of individual messages in bytes 
-s num ML-DSA parameter set: 44, 65, or 87 (default: 44) 
```

### Timing without signature encoding

The `timing_no_encode` harness is used like `timing`, but stops before the final signature encoding step.

```
$ ./timing_no_encode -i messages.bin -o sigs.bin -t raw_times.bin -k sk.pem -n 32 -s 44
```

### Timing with per-sample raw private keys

The `key_timing` harness signs each message with a corresponding raw ML-DSA private key from a concatenated key file.

```
$ ./key_timing -i messages.bin -o sigs.bin -t raw_times.bin -k schedule.bin -n 32 -s 44
```

Arguments:
```
-i file  File with concatenated messages to sign 
-o file  File where to write the signatures 
-t file  File where to write timing data 
-k file  File with concatenated raw ML-DSA private keys 
-n num   Length of individual messages in bytes 
-s num   ML-DSA parameter set: 44, 65, or 87
```

### Timing with per-sample raw private keys without signature encoding

The `key_timing_no_encode` harness is used like `key_timing`, but excludes the final signature encoding step from the measured operation.

```
$ ./key_timing_no_encode -i messages.bin -o sigs.bin -t raw_times.bin -k schedule.bin -n 32 -s 44
```

### Timing rejection-window test vectors

The `rejection_timing` harness is used with test vectors generated by the [rejection test-case generator](../scripts/rejection_tc_generator.py). It reads one 32-byte key seed and one message per sample, signs the message, and records the timing.

```
$ ./rejection_timing -i messages.bin -k keys.bin -e signatures.bin -t raw_times.bin -n 32 -s 44
```

Arguments:

```
-i file  File with concatenated messages to sign 
-k file  File with concatenated 32-byte ML-DSA key seeds 
-e file  File with expected deterministic signatures (optional) 
-o file  File where to write produced signatures (optional) 
-t file  File where to write timing data 
-n num   Length of individual messages in bytes 
-s num   ML-DSA parameter set: 44, 65, or 87
```

The `-e` option can be used to verify that NSS produces the same deterministic signatures as the generator. If `-o` is provided, the produced signatures are written to that file. If `-o` is ommited, only timing data is written.

### Timing rejection-window test vectors without signature encoding

The `rejection_timing_no_encode` harness is used like `rejection_timing`, but excludes the final signature encoding step from the measured operation.

```
$ ./rejection_timing_no_encode -i messages.bin -k keys.bin -e signatures.bin -t raw_times.bin -n 32 -s 44
```

## Key handling
`readpem.c` and `readpem.h` are used to import external ML-DSA private keys into NSS.

The `timing` and `timing_no_encode` harnesses import one PKCS#8 PEM private key as an NSS session key before the signing loop.

The `key_timing` and `key_timing_no_encode` harnesses import one raw ML-DSA private key per measurement sample.

The `rejection_timing` and `rejection_timing_no_encode` harnesses derive one ML-DSA private key per sample from a 32-byte key seed using `MLDSA_NewKey()`, then import the raw private key material into the NSS PKCS#11 signing path.

## Limitations
The ***_no_encode** harnesses do not work with an unmodified NSS installation. They require the timing overlay to be applied to the NSS source and the resulting freebl library to export **MLDSA_GetLastCoreCycles()**.

Only deterministic ML-DSA signing is used.
