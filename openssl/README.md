# OpenSSL Test Harness for ML-DSA Side-Channel Analysis Toolkit

This directory contains helper programs to perform side-channel timing
analysis on OpenSSL's ML-DSA implementation (provider-based EVP API).

## Building

1. Install OpenSSL with ML-DSA support (3.x development headers and libraries;
   your distro package or a local build with ML-DSA enabled).

2. Compile the test harness

```console
$ cd openssl
$ gcc -o timing timing.c -lcrypto
$ gcc -o timing_no_encode timing_no_encode.c -lcrypto
$ gcc -o key_timing key_timing.c -lcrypto
$ gcc -o key_timing_no_encode key_timing_no_encode.c -lcrypto
$ gcc -o rejection_timing rejection_timing.c -lcrypto
$ gcc -o rejection_timing_no_encode rejection_timing_no_encode.c -lcrypto
```

If OpenSSL is installed in a custom prefix, add `-I.../include`, `-L.../lib`, and
set `LD_LIBRARY_PATH` when running.

## Usage

### Timing with a single PEM private key

The `timing` harness signs concatenated messages with one PEM-encoded ML-DSA private key.

```
$ ./timing -i messages.bin -o sigs.bin -t raw_times.bin -k sk.pem -n 32 -s 44
```

Arguments:
```
-i file  File with concatenated messages to sign 
-o file  File where to write the signatures 
-t file  File where to write timing data 
-k file  File with the ML-DSA private key in PEM format 
-n num   Length of individual messages in bytes 
-s num   ML-DSA parameter set: 44, 65, or 87
```

### Timing without signature encoding

The `timing_no_encode` harness is used like `timing`, but stops before the final signature encoding step.

```
$ ./timing_no_encode -i messages.bin -o sigs.bin -t raw_times.bin -k sk.pem -n 32 -s 44
```

### Timing with per-sample raw private keys

The `key_timing` harness signs each message with a corresponding raw ML-DSA private key from a concatenated key file.

```
$ ./key_timing -i messages.bin -o sigs.bin -t raw_times.bin -k schedule.bin -n 32 -s 65
```

Arguments:
```
-i file  File with concatenated messages to sign 
-o file  File where to write the signatures 
-t file  File where to write timing data 
-k file  File with concatenated raw ML-DSA private keys 
-n num   Length of individual messages in bytes 
-s num   ML-DSA parameter set: 44, 65, or 87
```

### Timing with per-sample raw private keys without signature encoding

The `key_timing_no_encode` harness is used like `key_timing`, but excludes the final signature encoding step from the measured operation.

```
$ ./key_timing_no_encode -i messages.bin -o sigs.bin -t raw_times.bin -k schedule.bin -n 32 -s 65
```

### Timing rejection-window test vectors

The `rejection_timing` harness is used with test vectors generated by the [rejection test-case generator](../scripts/rejection_tc_generator.py). It reads one 32-byte key seed and one message per sample, signs the message, and records the timing.

```
$ ./rejection_timing -i messages.bin -k keys.bin -e signatures.bin -t raw_times.bin -n 32 -s 44
```

Arguments:

```
-i file  File with concatenated messages to sign 
-k file  File with concatenated 32-byte ML-DSA key seeds 
-e file  File with expected deterministic signatures (optional) 
-o file  File where to write produced signatures (optional) 
-t file  File where to write timing data 
-n num   Length of individual messages in bytes 
-s num   ML-DSA parameter set: 44, 65, or 87
```

The `-e` option can be used to verify that OpenSSL produces the same deterministic signatures as the generator. If `-o` is provided, the produced signatures are written to that file. If `-o` is ommited, only timing data is written.

### Timing rejection-window test vectors without signature encoding

The `rejection_timing_no_encode` harness is used like `rejection_timing`, but excludes the final signature encoding step from the measured operation.

```
$ ./rejection_timing_no_encode -i messages.bin -k keys.bin -e signatures.bin -t raw_times.bin -n 32 -s 44
```

## Limitations

Timing output on `-t` is **binary** (8 bytes per sample), not the text
`raw times` format. Use `extract.py` with `--binary 8` (and set
`--clock-frequency` appropriately for cycle counters) when classifying.

The `timing_no_encode`, `key_timing_no_encode`, and `rejection_timing_no_encode` harnesses depend on a patched OpenSSL build that records the internal ML-DSA signing-core timing in `ossl_ml_dsa_last_core_cycles`.
