# dilithium-py Test Harness for ML-DSA Side-Channel Analysis Toolkit

This directory contains Python scripts to measure ML-DSA signing using the
**dilithium-py** reference implementation.

## Building

Run the scripts with Python in an environment where `dilithium-py` is installed.

## Usage

### Timing with a single PEM private key

The `timing.py` harness signs concatenated messages with one PEM ML-DSA private key. The message size is configurable, with 32 bytes used by default.

```
$ python3 timing.py -i messages.bin -o signatures.bin -t timings.csv -s mldsa-44 -k sk.pem --size 32
```

Arguments:
```
-i file     File with concatenated messages to sign
-o file     File where to write the signatures
-t file     File where to write timing data
-k file     File with the ML-DSA private key in PEM format
-s num      ML-DSA parameter set: 44, 65, or 87
--size num  Length of individual messages in bytes
```

### Timing without signature encoding

The `timing_no_encode.py` harness is used like `timing.py`, but excludes signature packing from the timed region.

```
$ python3 timing_no_encode.py -i messages.bin -o signatures.bin -t timings.csv -s mldsa-44 -k sk.pem --size 32
```

### Timing with per-sample raw private keys

The `key_timing.py` harness signs each message with a corresponding raw ML-DSA private key from a concatenated key file.

```
$ python3 key_timing.py -k schedule.bin -d messages.bin -t raw_times.csv -o signatures.bin -s 44
```
Arguments:
```
-i file     File with concatenated messages to sign
-o file     File where to write the signatures
-t file     File where to write timing data
-k file     File with concatenated raw ML-DSA private keys
-s num      ML-DSA parameter set: 44, 65, or 87
```

### Timing with per-sample raw private keys without signature encoding

The `key_timing_no_encode` harness is used like `key_timing`, but excludes the final signature encoding step from the measured operation.

```
$ python3 key_timing_no_encode.py -k schedule.bin -i messages.bin -t raw_times.csv -o signatures.bin -s 44
```

### Timing rejection-window test vectors

The rejection_timing.py harness is used with test vectors generated by the [rejection test-case generator](../scripts/rejection_tc_generator.py).

```
$ python3 rejection_timing.py -k keys.bin -i messages.bin -e signatures.bin -t raw_times.csv -m 44
```

Arguments:
```
-k file     File with concatenated 32-byte ML-DSA key seeds 
-i file     File with concatenated messages to sign 
-e file     File with expected deterministic signatures (optional) 
-o file     File where to write produced signatures (optional) 
-t file     File where to write timing data 
-s num      ML-DSA parameter set: 44, 65, or 87
```

The `-e` option can be used to verify that `dilithium-py` produces the same deterministic signatures as the generator. If `-o` is provided, the produced signatures are written to that file. If `-o` is omitted, only timing data is written.

### Timing rejection-window test vectors without signature encoding

The `rejection_timing_no_encode` harness is used like `rejection_timing`, but excludes the final signature encoding step from the measured operation.

```
$ python3 rejection_timing_no_encode.py -k keys.bin -i messages.bin -e signatures.bin -t raw_times.csv -s 44
```

## Limitations

The `*_no_encode.py` scripts require a patched dilithium-py implementation that records the internal signing-core timing in scheme._last_time.
