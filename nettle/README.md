# Nettle Test Harness for ML-DSA Side-Channel Analysis Toolkit

This directory contains helper programs for side-channel timing analysis of Nettle's ML-DSA implementation.

The harnesses currently support only ML-DSA-65 and ML-DSA-87. ML-DSA-44 is not supported by this Nettle implementation.

## Building

1. Install Nettle

```console
$ git clone --depth=1 --branch=wip/dueno/ml-dsa2 https://git.lysator.liu.se/ueno/nettle.git
$ cd nettle
$ ./.bootstrap
$ ./configure --disable-documentation --prefix=$PWD/install
$ make
$ make install
```

2. Compile the test harness

```console
$ export PKG_CONFIG_PATH=.../nettle/install/lib/pkgconfig
$ gcc -ggdb3 -Wall -o timing timing.c $(pkg-config --cflags --libs nettle hogweed) 
$ gcc -ggdb3 -Wall -o timing_no_encode timing_no_encode.c $(pkg-config --cflags --libs nettle hogweed) 

$ gcc -ggdb3 -Wall -o key_timing key_timing.c $(pkg-config --cflags --libs nettle hogweed) 
$ gcc -ggdb3 -Wall -o key_timing_no_encode key_timing_no_encode.c $(pkg-config --cflags --libs nettle hogweed) 

$ gcc -ggdb3 -Wall -o rejection_timing rejection_timing.c $(pkg-config --cflags --libs nettle hogweed) 
$ gcc -ggdb3 -Wall -o rejection_timing_no_encode rejection_timing_no_encode.c $(pkg-config --cflags --libs nettle hogweed)
```

The *_no_encode harnesses require a patched Nettle build that exposes the internal signing-core timing value.

3. Run the test harness

```console
$ export LD_LIBRARY_PATH=.../nettle/install/lib
$ ./timing -i ../messages.bin -o sig -t timing -k sk.pem -n 100
```

## Usage

### Timing with a single PEM private key

The `timing` harness signs concatenated messages with one PEM-encoded ML-DSA private key.

```
$ ./timing -i messages.bin -o signatures.bin -t raw_times.bin -k sk.pem -n 32 -s 65
```

Arguments:

```
-i file     File with concatenated messages to sign 
-o file     File where to write the signatures 
-t file     File where to write timing data 
-k file     File with the ML-DSA private key in PEM format 
-n num      Length of individual messages in bytes 
-s num      ML-DSA parameter set: 65 or 87 (default: 65)
```

### Timing without signature encoding

The `timing_no_encode` harness is used like `timing`, but stops before the final signature encoding step.

```
$ ./timing_no_encode -i messages.bin -o signatures.bin -t raw_times.bin -k sk.pem -n 32 -s 65
```

### Timing with per-sample raw private keys

The `key_timing` harness signs each message with a corresponding raw ML-DSA private key from a concatenated key file.

```
$ ./key_timing -i messages.bin -o signatures.bin -t raw_times.bin -k keys.bin -n 32 -s 65
```

Arguments:

```
-i file     File with concatenated messages to sign 
-o file     File where to write the signatures 
-t file     File where to write timing data 
-k file     File with concatenated raw ML-DSA private keys 
-n num      Length of individual messages in bytes 
-s num      ML-DSA parameter set: 65 or 87 (default: 65)
```

### Timing with per-sample raw private keys without signature encoding

The `key_timing_no_encode` harness is used like `key_timing`, but excludes the final signature encoding step from the measured operation.

```
$ ./key_timing_no_encode -i messages.bin -o signatures.bin -t raw_times.bin -k keys.bin -n 32 -s 65
```

### Timing rejection-window test vectors

The `rejection_timing` harness is used with test vectors generated by the [rejection test-case generator](../scripts/rejection_tc_generator.py). It reads one 32-byte key seed and one message per sample, signs the message, and records the timing.

```
$ ./rejection_timing -i messages.bin -k keys.bin -e signatures.bin -t raw_times.bin -n 32 -s 65
```

Arguments:

```
-i file     File with concatenated messages to sign 
-o file     File where to write the signatures (optional) 
-t file     File where to write timing data 
-k file     File with concatenated 32-byte ML-DSA key seeds 
-e file     File with expected deterministic signatures (optional) 
-n num      Length of individual messages in bytes 
-s num      ML-DSA parameter set: 65 or 87 (default: 65)
```

The `-e` option can be used to verify that OpenSSL produces the same deterministic signatures as the generator. If `-o` is provided, the produced signatures are written to that file. If `-o` is ommited, only timing data is written.

### Timing rejection-window test vectors without signature encoding

The `rejection_timing_no_encode` harness is used like `rejection_timing`, but excludes the final signature encoding step from the measured operation.

```
$ ./rejection_timing_no_encode -i messages.bin -k keys.bin -e signatures.bin -t raw_times.bin -n 32 -s 65
```

## Limitations

It currently only supports ML-DSA-65 and ML-DSA-87.

The `*_no_encode` harnesses require a patched Nettle implementation that records the internal ML-DSA signing-core timing in `nettle_ml_dsa_last_core_cycles`.
